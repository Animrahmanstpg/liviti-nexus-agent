## Project Overview

**St Trinity - Channel Agent Portal** is a multi-role real estate SaaS platform for channel agents to manage properties, projects, leads, EOIs (Expression of Interest), sales offers, and advertising campaigns. It is a React/TypeScript SPA with a Supabase backend.

## Commands

```bash
npm run dev       # Start dev server at http://localhost:8080
npm run build     # Production build
npm run lint      # Run ESLint
npm run preview   # Preview production build locally
```

There is no test suite — this project has no unit or integration tests.

## Environment

Copy `.env` (it is already present) or set the following for a new environment:

```
VITE_SUPABASE_URL=https://<project-id>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=<anon-key>
```

## Architecture

### Tech Stack

- **React 18** + **TypeScript** + **Vite** (SWC)
- **Supabase** — auth, PostgreSQL database, storage (the entire backend)
- **TanStack React Query v5** — all server state / data fetching
- **React Router v6** — client-side routing with animated page transitions
- **shadcn/ui** + **Radix UI** — component primitives
- **Tailwind CSS** — styling (all tokens defined via CSS variables in `index.css`)
- **Framer Motion** — page transition animations
- **React Hook Form** + **Zod** — form handling and validation
- **Recharts** — data visualisation

### Entry Points and Routing

- `src/main.tsx` → `src/App.tsx` → `src/components/AnimatedRoutes.tsx`
- All routes except `/auth` and `/reset-password` are wrapped in `ProtectedRoute`, which checks `supabase.auth` and redirects to `/auth` when unauthenticated.
- Page transitions are handled by `PageTransition` (Framer Motion) wrapping every route.

### Supabase Integration

The Supabase client is a singleton at `src/integrations/supabase/client.ts`. Always import it as:

```ts
import { supabase } from "@/integrations/supabase/client";
```

Auto-generated TypeScript types live in `src/integrations/supabase/types.ts` — **do not edit this file manually**. Regenerate with the Supabase CLI when the schema changes.

All database access goes through React Query hooks that call the Supabase JS client directly. There is no separate API layer.

### User Roles & Access Control

Roles (`admin`, `agent`, `user`) are stored in the `user_roles` table and fetched via `useUserRole` / `useIsAdmin` hooks in `src/hooks/useUserRole.ts`. Row Level Security (RLS) is enforced on all sensitive Supabase tables — be aware of RLS policies when writing new queries or migrations.

### Key Data Models

Core tables (defined across `supabase/migrations/`):
- `properties`, `projects` — real estate listings and developments
- `leads`, `eoi_submissions`, `sales_offers` — sales pipeline
- `ad_campaigns`, `ad_creatives`, `ad_placements`, `ad_impressions`, `ad_clicks` — advertising system
- `page_views`, `property_views` — analytics (written by `useActivityTracker`)
- `notifications`, `notification_preferences` — notification system
- `custom_fields`, `field_groups` — dynamic/configurable form fields
- `user_roles` — role-based access control

### Component Structure

- `src/components/ui/` — shadcn primitives; don't modify these directly, regenerate via `npx shadcn@latest add <component>`
- `src/components/admin/` — all admin panel management components (user management, analytics, bulk import, campaign management, etc.)
- `src/components/ads/` — advertiser-facing components
- `src/hooks/` — custom hooks for cross-cutting concerns (role, notifications, favorites, activity tracking)
- `src/pages/` — one file per route; pages are thin orchestrators that compose components
- `src/types/` — shared TypeScript type definitions
- `src/utils/` — utility functions including Excel/CSV bulk import logic

### Styling Conventions

All design tokens (colours, radius, shadows, gradients) are CSS custom properties defined in `src/index.css`. Tailwind maps to these via `tailwind.config.ts`. Use the semantic token names (`bg-primary`, `text-muted-foreground`, `border`, etc.) rather than hardcoded colour values.

Custom fonts:
- `font-sans` → TASA Orbiter Display (body)
- `font-display` → Playfair Display (headings)

### Path Aliases

`@/` maps to `src/`. Always use this alias for imports rather than relative paths.

### Database Migrations

Schema changes go in `supabase/migrations/` as timestamped SQL files. The project uses the Lovable-generated UUID naming convention for migration files. Apply locally with `supabase db push` or via the Supabase dashboard.
